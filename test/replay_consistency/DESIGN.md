# Replay Consistency 设计

`Event.StateDelta` 契约：runner 始终把 map 原样交给 `AppendEvent`，不会按 `app:`、`user:`、`temp:` 或裸 key 自动调用独立 state API。未来若要支持独立作用域路由，必须增加显式 capability/scope 元数据，并通过真实后端矩阵验证；本轮不实现。

`StateMap` value 是 opaque bytes。snapshot 使用 `nil`、`json`、`utf8`、`base64` 标签，但合法 JSON 的 value 仍保存原始文本，不合并 key 顺序、空白、数字写法或等价转义；非法 UTF-8 使用 base64。`Event.StateDelta` 复用同一归一化，Event 其他结构化字段和 Track payload 继续做 JSON 语义比较。direct app/user 的 `List*States` 结果及 peer 继承状态也使用相同的字节精确比较；任何字节漂移都是 runner error，不能由 `allowed_diff` 放行。State 的 nil、空字节和纯空白分别表示为 `nil`、`utf8 ""` 和保留空白的 `utf8`，而 Track payload 继续使用独立的 `empty` kind。

`Run` 要求显式传入非空且无首尾空白的 run namespace；同一次后端比较复用该 namespace，每次重跑则生成新的 namespace。namespace 与 case name 共同派生 app、user 和 session 身份，隔离 session state、memory、summary 与 track；执行后保留持久化数据，不自动清理。`allowed_diff` 中的 quoted key 只有在解码后包含非 `*` 字面内容时才提供具体性，纯星号 quoted key 不能放行整个分区。

`Run` 在创建 session 前执行统一 fixture preflight，优先级固定为 track、event、summary、直接 state map 作用域、顺序 memory、并发 memory。该阶段预编码 track，使用与最终 snapshot 相同的 marshal-and-decode event normalization，生成完整且单调的 summary target 序列；`AppState` / `UserState` 接受无前缀或一层匹配的 `app:` / `user:` 前缀，已知跨作用域前缀仍作为 InMemory/SQLite 矩阵策略拒绝，未知前缀按普通 key 保留；`SessionState` 仍只拒绝 `app:` / `user:`，并保留 `temp:`、无前缀和自定义 key。App/User map 在 prepared expected state 中只剥离一个匹配前缀并深拷贝，原始 accepted map 仍传给后端；`List*States` 结果按已存储 key 形式复制，避免二次剥离。`flag` + `app:flag` 等 canonical collision 在任何后端调用前报告，`app:app:flag` 等额外前缀仍保留。随后按当前执行语义模拟带等价关系的顺序 memory alias registry：相同 canonical identity（topics 不参与）共享 group，未提供 `ResultAlias` 的 Add 也登记 active identity；live alias 只能重复绑定到同一 group，改绑到另一条 live memory 会在零后端调用状态失败，成功 Delete 后则可复用该 dead alias 且不会复活同组其他 alias；active identity 独立于 alias 数量，Delete 使 group 的全部 alias 失效，Update/ID 轮换迁移整个 group，不同 live group 的目标 identity 返回 collision 且不合并。任何静态 fixture 错误，包括非法直接 state map、canonical collision、已删除 alias 引用和 live alias 重绑定，都必须在零后端调用状态返回；执行阶段仍保留 state service、nil event、memory operation 等防御检查。后端写失败、真实 memory ID/查询结果、summary 输出、state scope 传播和运行后数据污染不能静态预检，越过该边界后的错误仍可能留下部分数据，最终 `BuildSnapshot` 也必须继续校验后端返回的 event。

`session/replaytest` 负责执行、归一化、比较和报告；`test` 保留后端装配与故障注入。Summary 用单调 `EventPrefix` 表达事件间的执行顺序；可选 `Backend.CreateSummary` 回调拥有准备和持久化的完整操作，并必须支持共享 backend 的并发 Run。Track 分别比较 map key、外层容器和内嵌 event；payload 覆盖完整 JSON 值域，并以标签区分 nil、空字节、JSON、UTF-8 和二进制。Backend 名称必须非空且无首尾空白，并提供显式的 `ReadAllMemories` callback；alias 与最终 snapshot 共用该 callback，只有后端 adapter 能证明读取完整时才返回 `complete=true`。nil memory entry、nil `Memory` payload、nil summary entry、nil track container 和 event normalize 失败均作为 runner error 返回，不会静默归一化；nil session 也不会跳过所提供 memories 的校验与归一化，track append 前的 session 读取返回 nil 时同样会由 runner 拒绝。事件归一化只忽略顶层 `Event.ID`，保留非 nil Response 的 `ID`、`Created` 和 UTC `Timestamp`，并保持 nil Response 与空 Response 的区别；`Event.StateDelta` 遵循 `AppendEvent` 的后端路由语义，runner 不根据 `app:` / `user:` 前缀推导独立 store 契约。只有直接 `Case.AppState`、`Case.UserState` 和 `Case.SessionState` 更新会触发独立作用域硬校验；无直接 state 的 case 不触发 ListApp/ListUser 或 peer 校验。peer 创建即使发生 fail-after-write 也会尝试限时清理。当前支持矩阵严格为 InMemory/SQLite，其 prefixed event delta 保留在 session-local state，并由真实 event-only 与 `state_scopes` 矩阵用例验证最终覆盖值、独立 store、peer 和 snapshot；MongoDB 不属于该矩阵。未来不同路由语义必须先通过显式 case/backend policy 建模。`Compare` / `CompareSnapshots` 对无法转换为 canonical JSON 的调用方快照返回 error，不 panic，也不返回部分 diff。map key 或 list index 缺失通过可选的 `left_missing` / `right_missing` report 字段表达，字段缺省表示对应侧存在；真实 JSON null 和 section 级 nil 不设置 missing 标记，旧的用户可构造 JSON sentinel 不再使用。`allowed_diff` 路径必须在声明的 section 根之后包含具体字段、quoted key 或固定索引，不能用 section 根通配符放行整个分区。Snapshot 字段集合保持不变，但 JSON state 的 `StateBytesSnapshot.Value` 从语义值改为原始字符串，相关 diff 定位到整个 `.value`；既有事件时间、精确 memory query、retry 和 `HasUnallowedDiffs` / `WriteReport` 其余语义保持不变。
