# Replay Consistency 设计

`Run` 要求显式传入非空且无首尾空白的 run namespace；同一次后端比较复用该 namespace，每次重跑则生成新的 namespace。namespace 与 case name 共同派生 app、user 和 session 身份，隔离 session state、memory、summary 与 track；执行后保留持久化数据，不自动清理。`allowed_diff` 中的 quoted key 只有在解码后包含非 `*` 字面内容时才提供具体性，纯星号 quoted key 不能放行整个分区。

`session/replaytest` 负责执行、归一化、比较和报告；`test` 保留后端装配与故障注入。Summary 用单调 `EventPrefix` 表达事件间的执行顺序；可选 `Backend.CreateSummary` 回调拥有准备和持久化的完整操作，并必须支持共享 backend 的并发 Run。Track 分别比较 map key、外层容器和内嵌 event；payload 覆盖完整 JSON 值域，并以标签区分 nil、空字节、JSON、UTF-8 和二进制。Backend 名称必须非空且无首尾空白，并提供显式的 `ReadAllMemories` callback；alias 与最终 snapshot 共用该 callback，只有后端 adapter 能证明读取完整时才返回 `complete=true`。nil memory entry、nil `Memory` payload、nil summary entry、nil track container 和 event normalize 失败均作为 runner error 返回，不会静默归一化；nil session 也不会跳过所提供 memories 的校验与归一化，track append 前的 session 读取返回 nil 时同样会由 runner 拒绝。只有直接 `Case.AppState`、`Case.UserState` 和 `Case.SessionState` 更新会触发独立作用域硬校验；`Event.StateDelta` 遵循 `AppendEvent` 的后端路由语义，runner 不根据 `app:` / `user:` 前缀推导独立 store 契约。peer 创建即使发生 fail-after-write 也会尝试限时清理。当前支持矩阵严格为 InMemory/SQLite，其 prefixed event delta 保留在 session-local state，并由真实 event-only 与 `state_scopes` 矩阵用例验证最终覆盖值、独立 store、peer 和 snapshot；MongoDB 不属于该矩阵。未来不同路由语义必须先通过显式 case/backend policy 建模。`Compare` / `CompareSnapshots` 对无法转换为 canonical JSON 的调用方快照返回 error，不 panic，也不返回部分 diff。map key 或 list index 缺失通过可选的 `left_missing` / `right_missing` report 字段表达，字段缺省表示对应侧存在；真实 JSON null 和 section 级 nil 不设置 missing 标记，旧的用户可构造 JSON sentinel 不再使用。`allowed_diff` 路径必须在声明的 section 根之后包含具体字段、quoted key 或固定索引，不能用 section 根通配符放行整个分区。既有事件时间、精确 memory query、retry、Snapshot schema 和 `HasUnallowedDiffs` / `WriteReport` 其余语义保持不变。
