# PromptIter 回归闭环设计

本示例把失败归因、提示词优化与发布判定分成可审计的连续阶段。基线评测先保留用例、指标、状态和原因；归因器按运行错误、工具轨迹、格式、路由、检索及最终回答的证据优先级，为每个未通过用例确定一个主因，无法确认时明确标为未分类，而不凭关键词臆断。PromptIter 只接收训练集及训练损失提示，生成完整 Profile 候选；外层闭环另行调用 Evaluation Service，以隔离的验证集比较候选和当前已发布 Profile。发布门禁要求证据形状完整、验证增益达标、硬失败数受控、关键用例与单用例退化均不过界，并校验累计调用、令牌、成本和时延预算；任一未知或失败条件都关闭发布。验证结果既不成为梯度，也不反馈给后续搜索，且被拒候选不会推进搜索状态，从数据隔离和状态转移两方面抑制过拟合。通过门禁后才输出完整候选 Profile；报告先在私有暂存目录生成并校验，再以目录重命名一次性发布，失败或拒绝运行不产生可推广文件，从而保证决策、证据和产物原子一致并可追溯。
