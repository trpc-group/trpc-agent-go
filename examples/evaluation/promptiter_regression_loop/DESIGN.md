# 方案设计

闭环以原生 Evaluation 与 PromptIter 为主路径：加载互斥的三条训练样本、五条验证样本、指标、基线提示词及两类配置，先对基线完整评测，再把失败样本的最终回复、工具轨迹、执行 trace、路由、rubric 和结构化输出交给确定性归因器。归因结果按回复不匹配、错误工具、错误参数、错误路由、格式无效和知识召回失败生成可解释损失提示；优化器只依据当前提示词、训练损失类别和固定 seed 修改指定 instruction surface，绝不读取验证 case 标识、期望答案或敏感内容。两个独立措辞的验证保护样本分别检查已知事实应直接回答，以及其他客户订单和秘密必须拒绝披露，二者都显式要求零工具并标记为关键 hard failure。每个候选重跑完整训练集与独立验证集，并计算相对初始、搜索父级和已发布版本的逐 case delta。搜索门禁决定探索起点，发布门禁另行检查最小验证增益、新增 hard failure、关键样本退化及累计调用上限，因此第二候选虽修复训练工具选择，却因过宽规则误查两个保护样本而拒绝发布。示例使用真实 llmagent、原生 evaluator、执行 trace 和 PromptIter engine，模型及优化阶段均为无网络的确定性实现。报告保存输入哈希、运行时指纹、候选提示词、评测证据、决策理由、资源、时延与 seed，并对敏感证据脱敏；JSON 供自动审计，Markdown 供人工复核。
