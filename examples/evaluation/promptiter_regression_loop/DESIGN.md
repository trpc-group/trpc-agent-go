# 方案设计

闭环以原生 Evaluation 与 PromptIter 为主路径：加载互斥的训练集、验证集、指标、基线提示词及两类配置，先对基线完整评测，再把失败样本的最终回复、工具轨迹、执行 trace、路由、rubric 和结构化输出交给确定性归因器。归因结果按回复不匹配、错误工具、错误参数、错误路由、格式无效和知识召回失败生成可解释损失提示；优化器只依据当前提示词、真实损失类别和固定 seed 修改指定 instruction surface，marker 仅用于防止重复规则。每个候选都重跑完整训练集与独立验证集，并计算相对初始、搜索父级和已发布版本的逐 case delta。搜索门禁决定后续探索起点，发布门禁另行检查最小验证增益、新增 hard failure、关键样本退化及累计调用上限，因此训练提升但关键验证样本退化的候选仍会被拒绝。示例使用真实 llmagent、原生 evaluator、执行 trace 和 PromptIter engine，底层模型及反向、聚合、优化阶段均为无网络的确定性实现。报告保存全部输入哈希、运行时指纹、候选提示词、评测证据、决策理由、资源、时延与 seed，并以固定证据上限和敏感字段脱敏控制产物规模；JSON 供自动审计，Markdown 供人工复核。
